# OpenCray 对话主导 UI 原型需求文档

- 日期：2026-09-07
- 状态：需求基线（待设计）
- 读者：UI/UX 设计 agent（本文档是设计输入，不预设视觉结论）
- 范围：移动端（手机优先）全量页面与组件需求盘点

---

## 1. 背景与目标

OpenCray 当前的移动端是四 tab 壳层（Chat / Skills / Files / Settings）。新原型放弃 tab 导航，改为**对话界面主导**的主流 agent 应用形态：会话流是唯一主界面，其余一切能力（文件、技能、设置、数字人）都从会话壳层进入。

本文档的目标：

1. 盘点新原型需要覆盖的**全部页面**（含入口与优先级）。
2. 盘点支撑这些页面的**组件库**，以最大化复用为原则（基础组件 + 组合模式两层结构）。
3. 给出每个组件的**形态清单**：共有多少种形态、每种长什么样、以什么形式呈现，并附对应的 UI/UX 呈现原则。
4. 明确交给设计 agent 前的开放决策项（第 9 节），不在本文档里擅自拍板。

信息来源于对现有 Flutter 实现的完整盘点（`flutter_app/lib/features/*`、`flutter_app/lib/core/*`），布局与 token 约束沿用 `docs/mobile-ui-layout-spec.md`。

## 2. 设计基调与全局约束

设计基调不变（沿用现有 spec）：

- Android 平台交互惯例 + Apple 式克制的视觉基调；扁平、弱阴影、靠分组与留白建立层级。
- 单列为主，`360dp` 为基准宽度档，`393dp` 为标准档；600dp+ 展开态本轮不做要求。
- 4dp 基础网格，8dp 节奏；间距/圆角/字号/组件高度全部走 token，不出现魔数。

设计 agent 需遵守的关键 token（摘自 `docs/mobile-ui-layout-spec.md`，详见原文）：

| 类别 | 要点 |
| --- | --- |
| 间距 | 4/8/12/16/20/24/32/40/48dp 九档；页面水平内边距 16（紧凑）/20（标准）dp |
| 圆角 | 8（胶囊徽章内小件）/12（输入框）/14（按钮）/16（卡片）/20（底部面板）/999（胶囊） |
| 字阶 | 大标题 28、区块标题 20、卡片标题 17、正文 15、次正文 14、标签 15（Medium）、说明 13；单屏可见字重 ≤ 3 级 |
| 组件高度 | 主/次按钮 52、行内按钮与图标按钮 40、单行输入 50、搜索 44、列表行 ≥60、设置入口行 ≥68、底导航规格本轮作废（无 tab） |
| 触达 | 最小触达目标 48dp |
| 深度 | 只允许背景对比、背景对比 + 1dp 描边、浮层微阴影三档；禁止大阴影/霓虹/嵌套卡片堆叠 |
| 主题 | 浅色 + 深色双主题；语义色沿用现有 palette（primary/success/warning/danger 各含 tint/border/mark） |
| 语言 | 中英双语文案（现有页面已双语，原型需按中文为主呈现） |

## 3. 信息架构与导航模型

### 3.1 总原则

- **没有底部 tab**。会话流是应用首页与常驻界面。
- 次级能力一律为**推入式页面**（水平转场）或**浮层**（面板/对话框/全屏 sheet），从会话壳层进入。
- 会话页保持单焦点：不允许多窗格分栏。
- 浮层体系固定四类：底部面板（选择/操作/表单）、对话框（确认/输入/令牌）、全屏 sheet（运行检查器）、全屏预览（图片/文本）。所有"弹东西"的需求必须落进这四类之一，不新增浮层种类。

### 3.2 导航结构

```
会话主页（唯一常驻界面）
├─ 左侧：会话抽屉（近期会话、新建会话）
├─ 顶栏：抽屉入口、自动化模式印记（SAFE/AUTO/DEV）、溢出区
├─ 输入区：文本输入 + 附件 + 命令 + 待办 + 中断
│
├─ 推入页面：文件工作台、技能库、设置（含全部设置子页栈）、Agent 管理
├─ 全屏 sheet：运行检查器（可驻留监听实时更新）
├─ 全屏预览：图片（缩放）、文本（只读）
├─ 底部面板/对话框：各类选择器、操作菜单、确认框
└─ 会话内浮层：消息长按菜单、多选工具栏、审批面（替换输入区）
```

### 3.3 深层页面栈规则

- 设置内部允许页面栈（子页再进子页），最多两层（如 设置 → 安全与限制 → 敏感动作）。
- Agent 创建页允许子编辑器栈（8 个子编辑页）。
- 每层子页必须有明确的返回标签（回到父页名），不允许裸返回箭头。
- 会话主页自身**不进入**任何页面栈底部——它永远是栈底。

## 5. 组件体系总览与复用策略

组件分两层：

- **基础组件**（第一、二组，18 类）：真正的设计系统原子——按钮、输入、开关、卡片、列表行、顶栏、浮层等。所有页面只允许用它们拼装。
- **组合模式**（第三~八组，43 类）：业务语义组件（消息气泡、审批卡、服务器卡等）。每个组合模式在文档里标注了它由哪些基础组件构成，设计时应抽公共形态回填基础组件，而不是各画各的。

**形态计数口径**：形态 = 该组件需要单独出图的视觉变体，含关键交互状态（如忙碌、禁用、选中）。不含纯动效中间帧。

## 7. 全局模式（跨页面一致性要求）

| 模式 | 要求 |
| --- | --- |
| 加载 | 首次加载整页骨架；切换已知会话/目录用骨架而非空白；所有周期性静默刷新（文件 2s、技能 2s、端侧模型下载 1s）保持内容在屏不闪 |
| 刷新 | 统一拉刷新组件；手势期间不显示忙碌指示；刷新失败不破坏现有内容 |
| 反馈 | 当前实现 toast（文件）与 SnackBar（技能）混用——**原型必须统一为一种轻提示形态**（形态由设计 agent 定）；成功保存类反馈优先内联状态胶囊而非弹出 |
| 自动保存 | LLM/个性化/媒体/网络/通知均去抖自动保存（260–350ms）+ 队列合并 + 失败回滚；保存状态用内联"保存中…"指示，不打断编辑 |
| 危险操作 | 三级递进：行内危险色 → 对话框确认（删除）→ 令牌输入武装（记忆/灵魂重置）；破坏性提交配中等触觉 |
| 空态 | 每个可空页面必须有空态卡（中性/强调色调），给下一步指引；错误态一律危险卡 + 重试 |
| 动效 | 200–350ms；语义化：推入=层级、淡入切滑=状态变化、stagger 入场=新列表；同一语义全应用一种动效；尊重系统"减弱动画" |
| 多选 | 统一"长按进入 + 点选 + 工具栏在底"心智（消息、文件、技能安装复用）；进入/退出有明确视觉切换（顶栏/输入区变形） |
| 无障碍 | 状态永不只靠颜色（高风险徽章图标+文字示范了标准）；触达 ≥48dp；文字对比度达 AA；语义标签完整（图标按钮必须有语义名） |
| 深浅色 | 所有语义色成对设计（base/tint/border/mark 四值）；玻璃/渐变效果需给出深色版 |
| 双语 | 中文为主呈现，文案长度按英文 +30% 冗余设计，不截断爆炸 |

## 8. 交付物要求（给设计 agent）

1. **画板尺寸**：360×800（基准档）与 393×852（标准档）两套关键页；其余页面只出基准档。
2. **组件库先行**：先交 6.1 + 6.2 基础组件全形态画板，评审后再拼页面；组合模式若发现可再抽象，回填基础组件。
3. **状态覆盖**：P0/P1 页面必须覆盖 默认/加载（骨架）/空/错误/忙碌 五态；P2 至少默认态。
4. **双主题**：P0 页面 + 全部基础组件出深色版；P1 及以下浅色即可。
5. **命名规范**：`组件名-形态名`、`页面名-状态名`，与本文档词条对应。
6. **红线**：P0 三页（会话主页、会话抽屉、LLM 设置）出红线标注（间距/字号/圆角用 token 名）。
7. **token 对齐**：交付的间距/圆角/字阶必须能映射回第 2 节 token 表；新 token 需单独说明理由。
8. **工具**：仓库既有原型为 Pencil/SVG（如 `docs/chat-multi-select-pencil-prototype.svg`）；工具沿用以设计 agent 顺手为准，但组件库必须可复用、可导出。
9. **优先顺序**：P0 → P1 → P2；P0 内部先会话主页（含输入区全状态）→ 审批卡 → 基础控件。

## 9. 开放设计决策（需用户/设计 agent 拍板，本文档不预设）

1. **次级能力入口**：无 tab 后，文件/技能/设置/Agent 从哪进？（候选：顶栏溢出菜单、会话抽屉底部导航区、输入区命令面板、全屏命令入口。）这决定会话壳层的 chrome 形态，是 P0 前置决策。
2. **会话抽屉职责**：抽屉只管会话，还是兼作全局导航（下挂文件/技能/设置入口）？
3. **欢迎/引导页**：`docs/pencil-welcome.pen` 有欢迎页原型痕迹，但现行应用无此页面。新原型是否包含首次启动引导？
4. **轻提示统一形态**：toast 与 SnackBar 二选一还是新设计（见第 7 节）。
5. **文件预览**：沿用对话框浮层还是改底部面板（现有 spec 的遗留开放问题）。
6. **技能详情**：操作全部收在底部面板是否足够，还是需要独立详情路由（现有 spec 的遗留开放问题）。
7. **个性化预设**：预设卡三选一还是改分段选择器（现有 spec 的遗留开放问题）。
8. **LLM 设置密度**：云端模式 5 卡信息量很大，是否引入折叠/分步（向导）模式，还是保持单页滚动。
9. **调试工具页面**（第 4.5 节 6 页）是否纳入本轮原型范围。建议整体延后，不影响主线。
10. **展开态（600dp+）**：本轮是否覆盖。建议不覆盖，先保证单列手机体验。
