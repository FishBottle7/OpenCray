## 1. 背景与目标

OpenCray 当前的移动端是四 tab 壳层（Chat / Skills / Files / Settings）。新原型放弃 tab 导航，改为**对话界面主导**的主流 agent 应用形态：会话流是唯一主界面，其余一切能力（文件、技能、设置、数字人）都从会话壳层进入。

本文档的目标：

1. 盘点新原型需要覆盖的**全部页面**（含入口与优先级）。
2. 盘点支撑这些页面的**组件库**，以最大化复用为原则（基础组件 + 组合模式两层结构）。
3. 给出每个组件的**形态清单**：共有多少种形态、每种长什么样、以什么形式呈现，并附对应的 UI/UX 呈现原则。
4. 明确交给设计 agent 前的开放决策项（第 9 节），不在本文档里擅自拍板。

信息来源于对现有 Flutter 实现的完整盘点（`flutter_app/lib/features/*`、`flutter_app/lib/core/*`），布局与 token 约束沿用 `docs/mobile-ui-layout-spec.md`。

## 2. 设计基调与全局约束

设计基调不变（沿用现有 spec）：

- Android 平台交互惯例 + Apple 式克制的视觉基调；扁平、弱阴影、靠分组与留白建立层级。
- 单列为主，`360dp` 为基准宽度档，`393dp` 为标准档；600dp+ 展开态本轮不做要求。
- 4dp 基础网格，8dp 节奏；间距/圆角/字号/组件高度全部走 token，不出现魔数。

设计 agent 需遵守的关键 token（摘自 `docs/mobile-ui-layout-spec.md`，详见原文）：

| 类别 | 要点 |
| --- | --- |
| 间距 | 4/8/12/16/20/24/32/40/48dp 九档；页面水平内边距 16（紧凑）/20（标准）dp |
| 圆角 | 8（胶囊徽章内小件）/12（输入框）/14（按钮）/16（卡片）/20（底部面板）/999（胶囊） |
| 字阶 | 大标题 28、区块标题 20、卡片标题 17、正文 15、次正文 14、标签 15（Medium）、说明 13；单屏可见字重 ≤ 3 级 |
| 组件高度 | 主/次按钮 52、行内按钮与图标按钮 40、单行输入 50、搜索 44、列表行 ≥60、设置入口行 ≥68、底导航规格本轮作废（无 tab） |
| 触达 | 最小触达目标 48dp |
| 深度 | 只允许背景对比、背景对比 + 1dp 描边、浮层微阴影三档；禁止大阴影/霓虹/嵌套卡片堆叠 |
| 主题 | 浅色 + 深色双主题；**色板见 2.1 节（权威值，取自 `Newlook.pen` 的 17 个主题化变量）**，中性色向主题蓝偏移、禁用渐变 |
| 语言 | 中英双语文案（现有页面已双语，原型需按中文为主呈现） |

### 2.1 色板规范（原型权威值）

色板取自 `Newlook.pen` 的 17 个主题化变量，实现时以此为准。**设计原则：中性色不用纯黑纯白，全部向主题蓝（hue ≈ 215）偏移**，深色是"蓝墨"、浅色是"蓝雾"；强调色在两个主题下分别调整明度以保证对比度。

变量在 `.pen` 中注册了 `mode: dark | light` 主题轴，节点只引用变量名（`$bg`、`$text`…），换肤靠屏幕根的 `theme` 属性，不复制样式。

#### 中性色

| Token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `bg` | `#0C111C` | `#F1F4FA` | 页面底色（非纯黑/纯白，带蓝倾向） |
| `surface` | `#121826` | `#FBFCFE` | 卡片、输入框、顶栏元素 |
| `surface-2` | `#1A2334` | `#EEF3FB` | 抬升一级的面（次级卡片） |
| `dim` | `#202B40` | `#E3EAF6` | 时间胶囊、图标底座、chips |
| `row` | `#161E2E` | `#F3F6FC` | 列表行底 |
| `stroke` | `#232E44` | `#DCE4F2` | 1dp 描边、分割线 |

#### 文字

| Token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `text` | `#EFF4FC` | `#17233A` | 主文字（冷白 / 蓝黑，非纯色） |
| `secondary` | `#9FADC2` | `#5D6B84` | 次级说明、卡片正文（带蓝的灰） |
| `tertiary` | `#6C7A92` | `#8794AB` | 占位符、元信息、折叠思考行 |

#### 强调与语义色

| Token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `blue` | `#5A9EF8` | `#2E7FE0` | 主色：发送钮、用户气泡、SAFE 标识、波形、运行中 |
| `blue-soft` | `#16283F` | `#E3EEFC` | 主色浅底：当前会话高亮、语音卡背景 |
| `green` | `#3ED698` | `#1FA971` | 成功、工具完成 |
| `orange` | `#F0A93F` | `#C77E17` | 等待审批（WAITING 徽标文字） |
| `orange-soft` | `#322613` | `#FBEED3` | WAITING 徽标底 |
| `warm-text` | `#EFC46E` | `#8A6410` | 提示类文案 |
| `warm-bg` | `#2B2212` | `#F7EED6` | 提示类底色 |
| `indicator` | `#FFFFFF2E` | `#17233A26` | Home indicator（带透明度） |

#### 用色红线

- **禁止渐变**：主色一律实色 `$blue`。原型早期的蓝色渐变（`#2E7FE0 → #6FB6FF`）已全部压平，视觉过重且无法跟随主题。
- 中性色**不得**使用 `#000000` / `#FFFFFF` / 纯灰（`#888` 一类），必须用上表 token。
- 白色仅允许出现在主色块上的文字与图标（如蓝底按钮内的白字）。
- 语义色只用于状态表达，不做装饰。

### 2.2 输入区组件规格（P0）

输入区是本轮设计的核心，共 6 个状态，全部为 `.pen` 中的可复用组件，暗/亮双主题各出一版。

| 组件 | 状态 | 结构 | 关键规格 |
| --- | --- | --- | --- |
| `Composer` | 静默默认 | 单行框（占位符 + 麦克风）+ `+` + 发送 | 行高 44、圆角 14、内边距 12/14、间距 10；按钮 44×44；占位符 15sp `$tertiary` |
| `Composer Expanded` | 打字（多行草稿） | **融合卡**：草稿文字在上，控制行收进卡片底部 | 卡片圆角 20、内边距 14/14/10/14、间距 10；`+`/麦克风为 32 圆形 chips（`$dim` 底）；发送 36×36 圆角 12 |
| `Composer Voice` | 说话中 | **高融合卡**：实时转写文字在上，波形 + 计时 + 停止在下 | 同上卡片规格；底色 `$blue-soft`；波形 7 根 3dp 柱（`$blue`）；计时 13sp/600 `$blue`；停止 36×36 |
| `Composer Add Menu` | 点 `+` 之后 | 弹出卡从输入框上方顶起，三项：Image / File / Command | 卡宽 232、圆角 16、内边距 6；行高 44、圆角 12；图标座 28 圆角 8；右侧 meta 11sp `$tertiary`（`PNG · JPG` / `PDF · DOC` / `Run skill`） |
| `Composer Attached` | 已附文件 | chips 行（可 × 移除）+ 输入框 | chip 圆角 10、内边距 6/10、间距 8；文件名 13sp/500；× 图标 14 `$tertiary` |
| `Composer Generating` | Agent 运行中 | `⟳ Running <tool>…` 卡 + 中性停止钮 | 卡 44 高圆角 14；转轮图标 16 `$blue`；文案 13sp `$secondary`；停止 44×44 `$dim` 底（非主色，避免误触感） |

**状态流转**：`Default →（点麦克风）Voice →（点停止）Expanded →（发送）Default`；`Default →（点 +）Add Menu →（选文件）Attached`；发送后进入 `Generating`，可中断回 `Default`。

### 2.3 会话流呈现规范（P0）

- **AI 消息不用气泡**：平文直排在页面底色上（`$text`，行高 1.35），只有用户消息用气泡（`$blue` 实色底、白字、圆角 18、最大宽 246）。
- **思考过程折叠成一行**：`⌾ Thought for 6s ⌄`（13sp `$tertiary` + 图标），点击展开。**不使用思考卡片**——该形态已废弃。
- **工具运行同样是一行**：`⟳ Running parse_logs in workspace…`（13sp `$tertiary`，转轮 `$blue`），完成后收起。
- **审批卡是唯一允许的重卡片**：白/深底 + 1dp `$stroke` + 圆角 18，WAITING 徽标（`$orange-soft` 底 / `$orange` 字），双按钮（主操作 `$blue` 实底白字 + 次操作 `$bg` 底）。
- 时间分隔用 `$dim` 胶囊（`Today`），12sp `$secondary`。

### 2.4 导航壳层规范（P0）

- **顶栏**（`Chat Top Bar`，40 高）：左侧 32 圆形抽屉按钮，紧接环境 pill（`Local ▾`，`$surface` 底胶囊）+ `SAFE` 标识（12sp/600 `$blue`），右侧 32 圆形新建会话按钮。
- **会话抽屉**（300 宽，`$surface` 底 + 右侧微阴影）：品牌行 + SAFE 胶囊 → `New session` 主按钮（`$blue` 实底 44 高）→ 会话历史（按 TODAY / YESTERDAY 分组，当前会话 `$blue-soft` 高亮、meta 用 `$blue`）→ 弹性留白 → 1dp 分割线 → **Skills / Files / Settings 导航行**（48 高，32 图标座）。
- 抽屉遮罩 `#11111126`，覆盖全屏含状态栏。

## 3. 信息架构与导航模型

### 3.1 总原则

- **没有底部 tab**。会话流是应用首页与常驻界面。
- **常用度分层收纳**：高频能力（会话切换、Agent 切换、附件、命令、审批、中断、运行回看）在会话界面内或一步可达；中频能力（文件、技能）从壳层一步进入；低频且复杂的配置一律集中在设置域，会话壳层不放散落入口。
- 次级能力一律为**推入式页面**（水平转场）或**浮层**（面板/对话框/全屏 sheet），从会话壳层进入。
- 会话页保持单焦点：不允许多窗格分栏。
- 浮层体系固定四类：底部面板（选择/操作/表单）、对话框（确认/输入/令牌）、全屏 sheet（运行检查器）、全屏预览（图片/文本）。所有"弹东西"的需求必须落进这四类之一，不新增浮层种类。

### 3.2 导航结构

```
会话主页（唯一常驻界面）
├─ 左侧：会话抽屉（品牌行 + SAFE、新建会话、会话历史分组、底部 Skills/Files/Settings 导航行，见 2.4）
├─ 顶栏：抽屉入口、环境 pill、自动化模式印记（SAFE/AUTO/DEV）、新建会话（见 2.4）
├─ 输入区：文本输入 + 语音转写 + 附件 + 命令 + 待办 + 中断（六态见 2.2）
│
├─ 推入页面：文件工作台、技能库、设置（含全部设置子页栈）、Agent 管理（设置连接组直达，见 10.1.4）
├─ 全屏 sheet：运行检查器（可驻留监听实时更新）
├─ 全屏预览：图片（缩放）、文本（只读）
├─ 底部面板/对话框：Agent 切换面板（入口待定，开放决策 8）、各类选择器、操作菜单、确认框
└─ 会话内浮层：消息长按菜单、多选工具栏、审批面（替换输入区）
```

### 3.3 深层页面栈规则

- 设置内部允许页面栈（子页再进子页），最多两层（如 设置 → 安全与限制 → 敏感动作）。
- Agent 创建页允许子编辑器栈（8 个子编辑页）。
- 每层子页必须有明确的返回标签（回到父页名），不允许裸返回箭头。
- 会话主页自身**不进入**任何页面栈底部——它永远是栈底。

## 5. 组件体系总览与复用策略

组件分两层：

- **基础组件**（第一、二组，18 类）：真正的设计系统原子——按钮、输入、开关、卡片、列表行、顶栏、浮层等。所有页面只允许用它们拼装。
- **组合模式**（第三~八组，44 类）：业务语义组件（消息单元、审批卡、服务器卡等）。每个组合模式在文档里标注了它由哪些基础组件构成，设计时应抽公共形态回填基础组件，而不是各画各的。

**形态计数口径**：形态 = 该组件需要单独出图的视觉变体，含关键交互状态（如忙碌、禁用、选中）。不含纯动效中间帧。

## 10. 功能侧审计（本次修订新增）

以"后端有什么功能 → 前端要什么 UI"的视角对现有能力做了一次全量盘点，结论分三类：**没分配到 UI 的功能**（10.1）、**冗余可精简的 UI**（10.2）、**容易被误补的边界澄清**（10.3），以及配套的**组件收敛映射**（10.4）。所有条目均已回写进第 4/6 节对应词条。

### 10.1 功能缺口：后端有、UI 未分配

| # | 功能 | 现状证据 | 分配去向 | 后端待办 |
| --- | --- | --- | --- | --- |
| 1 | **语音输入** | 媒体与语音设置里已有转写（STT）路由配置，但聊天界面没有任何麦克风入口——配置无人消费 | 静息输入框麦克风按钮 + 说话态（实时转写 + 波形），完整规格见 2.2 `Composer Voice`；转写路由配置页保留并在文案中说明"被输入区语音收音消费"（页面 #19） | 录音采集 → STT 路由 → 转写回填的链路尚未打通 |
| 2 | **会话重命名** | 抽屉长按菜单只有复制/删除，重命名无入口；桥方法面也没有 rename | 抽屉长按菜单第 3 项「重命名」（6.3 会话抽屉行 ④），复用 6.2 对话框②输入框 | 桥方法 `renameChatSession` |
| 3 | **MCP 添加服务器** | MCP 页只有服务器卡列表，没有添加入口；桥方法面无 add-server | MCP 页（#16）服务器卡列表尾部「添加服务器」入口，表单进 6.2 底部面板③表单模板 | 桥方法 + 服务器配置表单 |
| 4 | **Agent 管理入口** | 现设置首页分组排序把 Agents 组过滤掉了（`_homeEntryGroupOrder`），深链 `/settings/agents` 可达但无可见入口 | 双入口：设置首页连接组「Agents」行（页面 #15，P1）；会话侧 Agent 切换面板（页面 #7，P0，入口待开放决策 8） | 无（纯前端路由，桥已支持列表/选择） |
| 5 | **Agent 编辑/删除** | 桥只有 `createAgent` / `selectAgent`，没有改名、改配置、删除 | Agent 列表卡点击进入编辑，**复用 Agent 创建页与 8 个子编辑器模板**（页面 #35），不另起炉灶；删除走危险确认对话框 | 桥方法 `updateAgent` / `deleteAgent` |
| 6 | 技能内容编辑 | 技能安装后只能启停/更新/移除 | **明确不做**：技能内容编辑超出本轮范围，UI 只保留预览指令 | 无 |

### 10.2 冗余精简：UI 显得多余

| # | 对象 | 精简决策 | 理由 |
| --- | --- | --- | --- |
| 1 | API 集线页 | **取消独立页**（页面 #17 划线） | 纯导航跳板：一页只放 4 个入口行，无自身内容。网络&搜索、媒体&语音、沙箱提供商改为设置首页连接组直达；路由规则说明并入沙箱提供商页 |
| 2 | 技能库摘要统计卡 | 移除（页面 #9 已注明） | "共 N 个技能"信息量列表自身已表达，摘要卡是纯负担 |
| 3 | MCP 服务器卡 6 条明细行 | **默认折叠**（6.6 服务器卡） | 信任/认证/就绪/传输/暴露/指引逐行常驻，扫读负担重；折叠态只露标题+状态胶囊+启停，展开才看披露 |
| 4 | 调试工具六页 | 维持 P2 并建议整体延后（开放决策 6） | 开发者向，不占主线设计产能 |

### 10.3 边界澄清：不是缺口，别补 UI

- **文件上传没有独立入口**：上传唯一路径是聊天附件（2.2 `Composer Attached`），由 Agent 写入/保存进工作区。文件工作台不做"上传按钮"。
- **定时任务没有创建 UI**：任务由 Agent 工具在会话中创建（后端 `ScheduledTaskRuntime`），UI 只负责查看、启停、贪睡、看历史（页面 #24/25）。
- **会话列表无文件夹/置顶/收藏层级**：抽屉只按时间分组（TODAY/YESTERDAY，见 2.4），不做二级组织。

### 10.4 组件收敛映射（同用途必须复用同组件）

| 用途 | 收敛到 | 覆盖场景 |
| --- | --- | --- |
| 供应商/模型选择 | 6.1 选择器行 + 6.2 底部面板①选择面板 | LLM 云端供应商、模型绑定子编辑器、媒体语音四服务路由 |
| 单选配置项 | 6.7 选择瓦片（单选勾选） | 策略四选项、模式、可塑性、称呼风格、子代理上下文 |
| 卡内字段编辑 | 6.1 文本输入⑤内联编辑行 / 开关②字段内嵌 | 各服务卡字段栈、搜索槽位字段、流式输出行 |
| 状态通告 | 6.1 状态卡四色调 | 空目录、搜索无结果、加载失败、禁用警示 |
| 轻反馈 | 原生 toast（已决，见第 7 节） | 保存成功类以外的所有轻提示 |
| 危险确认 | 6.2 对话框①危险确认（+③令牌用于不可逆） | 删除会话/技能/槽位、记忆与灵魂重置 |
| 附件展示 | 6.3 附件卡族（图片组/文件卡/语音卡/chips） | 聊天附件、Agent 媒体样本、参考图瓦片 |
| 添加内容入口 | 2.2 `+` 菜单（Image/File/Command） | 仅聊天输入区专属，不泛化成全局"添加"按钮 |

### 10.5 审计影响汇总

- **页面条目**：41 条 → 净 40 页（+Agent 切换面板、−API 集线）；技能库管理/安装为同页分段按 1 页计，实际需设计的独立模板约 39 个。
- **组件总数**：62 类 / 163 形态（会话流 43→45：消息单元 4→5 拆出思考折叠行、输入区 9→10 定为 2.2 六态基座 + 四个扩展态；其余组不变）。
- **后端待办清单**（供排期）：`renameChatSession`、MCP 添加服务器（桥方法 + 表单）、`updateAgent` / `deleteAgent`、语音收音→STT 路由→转写链路。
